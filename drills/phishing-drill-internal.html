方案成本优点缺点结论

2.1 Gophish 部署要点（Docker）

# 前置：Docker 环境已具备（asset-monitor 同机或独立）

# ① 用 named volume —— 不要用 bind mount 挂 /opt/gophish
#    /opt/gophish 是程序目录（gophish 二进制 + config.json + gophish.db 都在其中）
#    bind mount 一个空宿主机目录过去会整体遮蔽容器内文件，容器直接起不来
docker volume create gophish_data

docker run -d --name gophish \
  --restart unless-stopped \
  -p 127.0.0.1:3333:3333 \   # 管理界面：仅本机监听，见下方说明
  -p 443:443 \               # 落地页/追踪：必须 443，见下方说明
  -v gophish_data:/opt/gophish \
  gophish/gophish

# 初始密码：docker logs gophish 2>&1 | grep -i password
# 首登后立即改密 + 管理界面加 IP 白名单（只允许 IT 网段）
# 定期备份卷内 gophish.db（演练历史数据是合规留痕证据）：
#   docker run --rm -v gophish_data:/src -v $PWD:/backup alpine \
#     tar czf /backup/gophish-db-$(date +%F).tar.gz -C /src gophish.db
两个会直接导致演练失败的坑（务必照改）：

① 落地页端口必须是 443，不能用 8080。映射到 8080 时落地页 URL 形如 http://演练域:8080/…——非标准端口会明显拉低仿真度（员工看到端口就起疑，邮件网关也更易判定为危险），结果是演练数据偏乐观、失去参考价值。
正确做法：容器映射 -p 443:443，并在 config.json 中将 phish_server.listen_url 设为 0.0.0.0:443、use_tls 设为 true，配 Let's Encrypt 证书（与 2.2 保持一致）。

② 管理界面建议只监听 127.0.0.1。Gophish 管理端默认走 HTTP，管理员密码与全员行为数据明文传输；若整段暴露在办公网，等同于把演练数据开在明网上。生产做法：仅本机监听，通过 SSH 隧道或带 HTTPS 的反向代理访问。

2.2 发信基础设施（关键，决定进收件箱还是垃圾箱）

  • 专用域名：注册一个语义明确、但不含品牌形近字的演练域（建议 poppula-security-drill.com 这类，名称中带 drill / test 字样）。绝不用公司正式域发钓鱼邮件（会污染正式域信誉、误伤真实邮件）。
    不建议采用形近替换域名（如用数字 1 替换字母 l 的 poppu1a-…）：① 警觉员工一眼识破，演练数据反而偏乐观；② 从公司外部看这属于针对自家品牌的 typosquatting，可能被品牌保护系统或外部观察者误报为恶意域名，徒增解释成本。
  • DNS 三件套：SPF（v=spf1 指向发信 IP）、DKIM（2048 位密钥签名）、DMARC（p=none + rua 报告收件箱）。演练域的 p=none 是终态而非过渡态——演练邮件本就要求能送达，此处配 DMARC 的目的是通过 rua 报告监控域名信誉，不需要、也不应后续收紧到 quarantine / reject
  • 预热：正式演练前 2 周开始小流量发信（每天几十封正常内容），养域名信誉，否则全进垃圾箱导致演练数据失真
  • 落地页域名：同样用演练域，配 Let's Encrypt 证书（Let's Encrypt 免费且被信任，真实攻击者也这么干——这正是演练要教的点）

三、邮件模板库（基于 2026 真实威胁设计）

模板设计原则：每一套都对应一类真实在打的攻击（数据来源：CrowdStrike GTR 2026 / DBIR 2026），并在复盘时告知员工"这不是编的，今年真有公司这么被打了"。

模板诱饵设计对应真实威胁难度目标部门
T1 假验证码页面"请完成人机验证以查看共享文档"→ 落地页模拟 CAPTCHA，实际收集凭据CrowdStrike：假 CAPTCHA 诱饵 +563%，年度增长最快低全员
T2 密码过期通知"您的邮箱密码将于24小时后过期"→ 仿 SSO 登录页凭据钓鱼常青款（DBIR：凭据滥用居前列）低全员
T3 虚假发票/对账"10月采购对账单见附件"→ 附件为 HTML 凭据页或宏文档财务供应链诈骗（BEC）主力载体中财务/采购
T4 高管冒充转账
须 CEO 本人书面知情		仿 CEO/总经办邮箱发"紧急付款，我先上会"（纯文本无链接，测的是流程敬畏而不是识别能力）。因冒用高管名义，IT 负责人授权不足以覆盖其关系与流程风险，须额外取得 CEO 本人书面知情并提前与 CEO 办公室通气BEC——单笔损失最高的钓鱼类型（FBI IC3 年度损失数十亿美元级）高财务/高管助理
T5 IT 部门冒充"安全团队检测到异常登录，请验证身份"（ irony：我们用假的"安全通知"教大家识别假安全通知）语音钓鱼 vishing 的邮件版；利用对 IT 的天然信任高全员（第2轮+）

3.1 落地页与凭据处理（红线）

安全红线：落地页表单不存密码——前端收到提交事件即记录"该用户已提交凭据"，密码字段直接丢弃不发送。这是演练与真攻击的本质区别，也是对员工的承诺：演练不留任何人的密码。落地页底部保留小字免责："这是 poppula 安全团队组织的演练，您的密码未被记录"（提交后才显示，不打草惊蛇）。

#步骤操作细节责任人

五、度量体系（KPI 定义先于执行）

指标定义（分子/分母）行业基准我们的目标
进箱率
新增 · 数据质量前置指标		成功进入收件箱 / 发送数（投放前用 Gmail / Outlook / 企业邮箱种子账号实测）—>90%；低于 80% 本轮数据作废、重投
打开率触发追踪像素 / 发送数30-40%参考值（不做考核）
点击率点击链接 / 打开数（CTOR）首轮 ~30%，成熟 <10%年内 30%→10%
提交率提交凭据 / 打开数首轮 ~10%<3%
上报率通过任意通道上报 / 打开数成熟 >50%逐轮上升（最优先指标）
上报时延首封上报时间 - 发送时间小时级→分钟级中位数 <30 分钟
复发率上轮点击本轮再点 / 上轮点击数—<20%（教育有效性验证）
口径修正：分母为什么从「发送数」改为「打开数」
本方案 2.2 已强调「邮件全进垃圾箱会导致演练数据失真」——既然如此，用发送数作分母就会把「根本没看到邮件」的人算成「看到了但没点」，系统性低估真实风险。

更麻烦的是跨轮次对比会失真：这一轮进箱率高、下一轮低，点击率的波动可能只反映投递质量，而与员工意识无关。

做法：主指标统一采用 CTOR（以打开数为分母），并把进箱率单列为数据质量前置指标——进箱率不达标时，本轮所有行为指标不予采信。若历史上已按发送数口径出过报告，复盘时需显式标注口径变更点，避免趋势线断裂被误读。
上报率为什么最优先：点击率有下限（再训练也会有人手滑），但上报率没有上限——每多一个上报的员工，等于多了一个免费传感器。对照攻击者从入侵到横向移动的突破时间（breakout time）：CrowdStrike GTR 记录的平均值为 29 分钟、最快记录已缩短至 2 分 7 秒——在这个尺度上，只有分钟级的上报网络（数十名员工构成的覆盖面）才谈得上抢在横向移动之前拦截，单点技术检测做不到这个覆盖密度。

六、演练 × 邮件网关联动（每次演练都变成一次防御升级）

演练的复盘产出直接回流到网关配置——这是"演练→防御"的闭环：

演练发现网关动作
某模板点击率异常高提取模板特征（发件域/正文关键词/链接结构）→ 加为网关拦截规则
落地页被大量访问URL 分类加入网关黑名单（防真实攻击者复用同类页面）
附件被下载评估附件类型是否应默认隔离（对齐 CrowdStrike 建议：可执行附件零信任）
上报的内容被上报样本自动进安全团队审查队列（演练期与真实期同一通道，练的就是这个肌肉）

七、Splunk 集成（对齐现有 SOC）

演练事件进 Splunk 统一分析——与现有安全日志同平台，真实攻击来临时演练数据就是行为基线：

# Gophish 侧：开启 webhook，事件推送到接收端
# 接收端将事件转 syslog / HEC 到 Splunk：

# HEC 方式（推荐）
# 注意：不要加 -k（跳过证书校验）。Splunk 应配置可信证书，
#       否则等于把全员演练行为数据送进一条可被中间人接管的通道
curl https://splunk.poppula.com:8088/services/collector/event \
  -H "Authorization: Splunk <HEC_TOKEN>" \
  -d '{
    "index":"phish_drill",
    "sourcetype":"gophish:campaign",
    "event":{
      "campaign":"2026Q1-T2-password-expiry",
      "action":"clicked",          # sent/opened/clicked/submitted/reported
      "user_hash":"a3f1c9…",       # 邮箱 SHA-256，见下方「身份字段脱敏」
      "dept":"finance",
      "template":"T2",
      "ts":"2026-09-15T10:04:31+08:00"
    }
  }'
  • 独立 index + 角色级访问控制（必做）：演练数据写入独立索引 index=phish_drill，并配置角色级 ACL，仅安全团队可检索。Splunk 的可见范围远大于 Gophish——若放任在公共索引里，业务部门或 HR 就能搜到「某位员工点击了链接」，这将直接击穿管理层版承诺的「不与绩效挂钩」，同时构成个人信息违规。此项未落实前，不要向 Splunk 发送任何演练数据
  • 保留期对齐：indexes.conf 中该索引的 frozenTimePeriodInSecs 须与「12 个月后匿名化」保持一致，避免出现 Gophish 侧已匿名化、Splunk 侧仍留存完整记录的情况
  • 身份字段脱敏：事件体中的邮箱建议以哈希值（user_hash）入湖，个人明细仅保留在 Gophish 本地用于定向复训；看板按 dept / template 维度聚合即可，无需个人身份字段
  • sourcetype 规范：gophish:campaign，字段 action / campaign / template / dept / user_hash——可直接做 CIM 映射（对齐 SOC 标准化方向）
  • 看板：按部门 / 模板 / 动作的时间序列；与邮件网关真实拦截量叠加对比（演练命中率 vs 真实攻击拦截率的关联视图）
  • LLM 研判挂钩：演练事件流与真实上报共用一条管道——LLM 研判真实邮件时可引用「该用户历史演练行为」做加权（高复发用户的上报误判率更高，需更仔细研判）。注意：该用途依赖个人维度数据，须严格限定在安全团队角色内，且不得输出至任何对员工可见的界面或报表

八、风险控制与常见坑

风险控制措施
演练被当成真实事件引发业务恐慌① 书面授权+关键岗提前报备 ② 发送时间避开月初月末财务高峰 ③ 中止预案（发出"停止演练"全员通知的预置模板）
员工信任受损（"IT 钓我们"的抵触）① 不与绩效挂钩、不点名（管理层版已声明）② 演练通报只讲统计不讲个人 ③ 教育页语气是"教你赢"不是"抓到你" ④ 明确承诺不存密码
演练邮件外泄被截图发到外网/客户模板落地页明确标注公司名与免责（查看源码可见但不显眼）；不做丑化公司或高管的诱饵内容
域名信誉反噬演练域与正式域完全隔离；DMARC rua 监控；演练域 SPF 明确限定发信源
合规/隐私（员工行为数据）数据最小化（只记动作不存密码）；访问权限仅安全团队；保留期 12 个月后匿名化；演练前在 IT 制度中备案
下一步（按序执行，授权在前）：
第 0 步 · 先做　☐ 向管理层提交授权申请（用配套管理层版汇报）并同步完成 IT 制度备案（个人信息处理依据）
第 1 步　☐ 注册演练域名 + DNS 三件套配置（SPF / DKIM / DMARC）　域名注册与 DNS 生效耗时较长，可与审批并行推进
第 2 步　☐ Docker 部署 Gophish + 管理界面加固（443 落地页、named volume、改密、仅本机监听）
第 3 步　☐ Splunk 独立 index + 角色 ACL 打通（务必先配好访问控制，再灌数据）
第 4 步　☐ 制作首轮 T1/T2 模板，先发给自己人（IT 部门）试测——自己人都识别不了就别发全员
第 5 步　☐ 种子邮箱验证进箱率（>90% 方可正式投放）

为什么把授权提到第 0 步：原清单把「申请授权」放在最后，但时间线第 1-2 周就要开始搭建基础设施——若授权未获批准，前期投入即作废。因此授权与制度备案应前置；仅域名注册这类长耗时事项可与审批并行。
